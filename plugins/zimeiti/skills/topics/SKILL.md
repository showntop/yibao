# 选题推荐（topics）

用户问「写什么」或直接点名「做一个关于 X 的内容」，要的都是**带判断的候选建议**，不是看板罗列，也不是热榜原文。

## 流程

0. **用户已点名主题**（「做一个关于 X 的短视频」这类）→ 跳过第 1 步热点，直接做 2~4（看库存/战绩/定位），然后围绕 X 出 2~3 个**候选角度**进第 5 步；没点名主题则从热点起。
1. **拉热点**：`zimeiti.ww_hotspots`（多平台聚合热榜）；不可用则退 `zimeiti.hot_topics`。
2. **看库存**：`zimeiti.list` 带 `quiet=true`（只要数据，**不要弹看板面板**）——新建议别和「写作中/待发布」撞车；「候选」里躺着的旧选题如被热点给了新由头，优先接续它。
3. **看战绩**：`zimeiti.stat_list` 扫历史发布数据——往表现好的方向/平台倾斜。
4. **对齐定位**：长期记忆里有用户的 IP 定位/受众/领域，只推与之相关的热点；定位无关的爆款不推。
5. **给建议**：2~3 个，每个给四件套：
   - 标题方向（一句话）
   - 切入角度（从哪个点写、给谁看）
   - 目标平台（公众号/知乎/小红书，说清为什么适合）
   - 为什么现在写（挂住哪个热点/哪条数据/哪条旧选题；热点给出原文链接）
6. **视频选题再加四件套**（用户要做视频、或题材明显适合视频化时必给）：
   - HKRR 标注：`happy`（快乐）、`knowledge`（知识）、`resonance`（共鸣）三项至少满足 1 项——这是选题的成立理由，一项都不沾的选题不要提；`rhythm`（节奏）一项标注「可行」或「存疑」（做不出节奏可行判断的选题是立项风险）
   - 钩型（悬念/反常识/利益承诺/身份代入……）
   - 目标视频平台（抖音/B站/YouTube，三平台算法权重不同，钩型和时长按平台派生）
   - 3 条文案级封面概念（封面前置是立项门槛：做不出好封面的选题直接淘汰；只出文字方案，不出图）
7. **问下一步**：「要不要把第 N 个转选题？」用户点头后才 `zimeiti.add`（source 记热点来源、url 带原文链接；视频选题把上一条的四件套一并传给 add——hkrr 传 JSON 字符串（四键 happy/knowledge/resonance/rhythm），cover_concepts 传恰好 3 条的 JSON 数组字符串），随后可接续写初稿流程（use_skill zimeiti:write）。视频选题确认后还可以直接「立项」：详情卡的立项动作会以选题创建项目并把选题挂进去（阶段门动作，需用户按印确认）。

## 原则

- 先建议、后动作：未经用户确认，不写看板、不开编辑器、不立项。
- 本流程里的取数调用一律带 `quiet=true`——面板只在用户点名「看看看板/素材库」时才弹。
- 在对话里直接给结论；不要只打开面板让用户自己翻。
- 宁缺毋滥：2 个准的胜过 5 个凑的；每条都必须有「为什么现在写」，没理由的热点不提。
- 热点和定位都不沾边时直说「今天没什么值得跟的」，另给 1 个不依赖热点的长线选题备选。
