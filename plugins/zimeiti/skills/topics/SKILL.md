# 选题推荐（topics）

用户问「写什么」，要的是**带判断的建议**，不是看板罗列，也不是热榜原文。

## 流程

1. **拉热点**：`zimeiti.ww_hotspots`（多平台聚合热榜）；不可用则退 `zimeiti.hot_topics`。
2. **看库存**：`zimeiti.list` 带 `quiet=true`（只要数据，**不要弹看板面板**）——新建议别和「写作中/待发布」撞车；「候选」里躺着的旧选题如被热点给了新由头，优先接续它。
3. **看战绩**：`zimeiti.stat_list` 扫历史发布数据——往表现好的方向/平台倾斜。
4. **对齐定位**：长期记忆里有用户的 IP 定位/受众/领域，只推与之相关的热点；定位无关的爆款不推。
5. **给建议**：2~3 个，每个给四件套：
   - 标题方向（一句话）
   - 切入角度（从哪个点写、给谁看）
   - 目标平台（公众号/知乎/小红书，说清为什么适合）
   - 为什么现在写（挂住哪个热点/哪条数据/哪个旧选题；热点给出原文链接）
6. **问下一步**：「要不要把第 N 个转选题？」用户点头后才 `zimeiti.add`（source 记热点来源、url 带原文链接），随后可接续写初稿流程（use_skill zimeiti:write）。

## 原则

- 先建议、后动作：未经用户确认，不写看板、不开编辑器。
- 本流程里的取数调用一律带 `quiet=true`——面板只在用户点名「看看看板/素材库」时才弹。
- 在对话里直接给结论；不要只打开面板让用户自己翻。
- 宁缺毋滥：2 个准的胜过 5 个凑的；每条都必须有「为什么现在写」，没理由的热点不提。
- 热点和定位都不沾边时直说「今天没什么值得跟的」，另给 1 个不依赖热点的长线选题备选。
