# Agent 原生工作台：从插件围墙到能力装配

> 状态：讨论稿 v2（discuss/agent-native-workbench 分支）
> 日期：2026-08-28
> 缘起：插件像一堵堵小墙——内容工作台的编辑器无法在别处使用。本文回答三个问题：**什么是 Agent 原生的工作台**、**对话与工作台表面的关系**、**如何在现有 Home 体系上落地**。

> v3 更新（2026-08-31）：回写视频创作 case 磨出的 **3+1 位模型**（三主导模式 × 四呈现密度 + peek 纪律），见「位的模型」节；项目实体 V1a 已落地（project.* 工具、目录骨架、L3 立项闸门），校准见 2026-08-30-project-entity-design.md §8。

## 1. 诊断：墙砌在哪一层

现有架构（`sidecar/src/yibao_brain/plugins.py`）已把 **tool 层**打通：所有插件工具注册进同一 `ToolRegistry`，LLM 可自由跨插件编排。墙在另外两层：

- **UI 层**：`plugins/zimeiti/panel/editor.html`（912 行单文件）与 toolbox `tools.html`（1035 行）各自内联整套设计 token 与交互，互相"照抄"；宿主唯一可复用 UI 是 schema 面板，表达力封顶于 list/detail/form/board 四种白名单组件。
- **调用层**：桥协议强制 `<pid>.` 前缀（`WebviewPanel.vue:114` + api.toml 前缀校验），面板**禁止**跨插件调用；api.toml `[[event]]` 声明了但推送通道未实现；插件内部代码复用靠复制（`wewrite.py` / `night_brief.py` 双抄本）。

"编辑器无法在别处使用"不是编辑器的问题，是**面板的属主问题**：UI 组件的所有权在插件，而不在工作台。

## 2. 核心论断：agent 与人是同一等价的操作者

> **界面上每个可操作动作，底部都是一次 tool 调用；每次 tool 调用的结果，都可被某个器渲染。**

用户点"接受 diff"与 agent 调 `editor.replace_range(...)` 收敛到同一入口、同一事件流。类比 VS Code command 系统：命令可被快捷键、菜单、扩展以同等身份触发，UI 只是命令的一种触发器。

检验清单：

1. 新任务类型出现时，**不写新页面**能否装配出可用工作台？
2. 面板上显示的任何东西，agent 能否**不通过截图**读到、改到？
3. 编辑器这类重交互组件，代码库里是否**只有一份**？
4. 用户手动操作与 agent 调用，是否收敛到**同一个工具、同一个事件流**？
5. 工作台是否有**生命周期**——随任务聚散，而不是固定布局等你入驻？

## 3. 分层：surface 是独立一层

```
能力层   plugins 的 tools / 数据 / 领域逻辑 —— 不知道像素
           ↓ 返回结构化结果 + 声明"适合被什么原语展示"
表面层   工作台：布局语法 + 共享原语 + 对象模型 + 裁决器
           ↓ 填充数据、路由事件
渲染层   编辑器 / diff / 列表等具体组件，桥协议
```

- 放进 tool 层 = 今天的墙（tool 携带 UI，UI 属主落在插件）。
- 只放前端 policy（现 `surface-policy.ts`）= agent 够不到，表面层成人类专属领地。
- 决定性一步：**表面层本身向 agent 暴露 tool 接口**（`surface.open/read`、`editor.*` 进 ToolRegistry，与插件 tool 平级）。

surface 拆为两样，工作台两者都拥有：

- **位（place）**：布局语法。inline / peek / stage / focus + 活动轨——已存在（`desktop/src/lib/surface/surface-policy.ts:7` 的 `Presentation` 四态 + HomeWindow 编排）。
- **器（instrument）**：共享原语。编辑器、diff、看板、列表、素材轨——从插件提升到宿主的重交互组件，**全库只有一份**。

插件填**数据 + 绑定声明**（schema 面板思路扩展到全部原语）；agent 做**把器摆进位**（装配）；裁决器守住信任不变量：stage/focus 必须有用户明确意图——留在裁决器代码里，不靠 agent 自觉。

## 4. 对话是基底：呼吸幅度矩阵（定稿）

陪伴式产品的调性是"它一直在"，不是"聊天记录一直在"。对话拆为两层：

- **溪口**：团子 + 输入框 + 最近一轮来回。**永远在场**——陪伴感的载体。
- **溪流**：完整历史消息。可查的档案，从溪口向上拉出（细脊展开），不常驻。

| 状态 | 表面 | 对话形态 | 场景 |
|---|---|---|---|
| 家态 | 零任务表面 | **对话区占 46%**，是主角；器物一瞥在右 | 无任务、闲聊、守夜回响 |
| inline/peek | 轻表面在右 | 对话流完整在左 | 高频来回（选题、确认素材） |
| stage | 器占中心 | **锚定批注**：任务相关对话钉到文档对应段落旁；溪口栖息在文档缘；历史收成细脊 | 认真改稿、协同写作 |
| focus | 单一器近乎全屏 | 只有角落团子 + 地平线发丝线 | 通读、演示、发布前终审 |

三条关键原则：

- **边说边指**：stage 态的输入框跟着选区走（"对这段内容提建议，或直接修改…"），锚定批注就是"选区+说话"的视觉形态。
- **出生证**：每个表面从生成它的那条消息长出来，牵引线连回源头消息；表面关闭后对话流里仍能找到出处。表面是对话的物化节点。
- **让位是姿态，不是本体**：三态主角始终是同一条对话主轴，stage/focus 里它自愿收缩让位给工作。

## 位的模型（3+1，2026-08-31 定稿回写）

在视频创作 case 里磨出、回写为工作台通用模型（推演过程与完整流转例见 2026-08-30-video-creation-workflow.md §6）。位不是四种并列布局，而是**两种正交刻度**：

- **三种主导模式**（工作台的态，回答"谁主笔"）：
  - 对话主导 = **agent 主导**：inline 来回，agent 提案、人点头；
  - stage = **协作**：器占中心，对话收成锚定批注，人和 agent 在同一对象上工作；
  - focus = **人主导**：agent 退化为器械——压缩成地平线读数与角落团子，满屏只剩对象和决定。
- **四种呈现密度**（对象的态，回答"占多少屏"）：inline / peek / stage / focus。

"3+1"的 +1 是 **peek**：它不是第四种工作模式，而是**器的预览态 + agent 主动性的礼貌出口**（守夜成果、提醒回响从这里探出头，不硬闯）。设计纪律：**peek 里只允许"看 + 一个决定"**——轻决定（意图登记如「立项」、导航如「修这段」、「知道了」）在 peek 完成；**L2/L3 按印永远回落到对话流里的闸门卡**——闸门是一个正式对话回合（agent 汇报 → 人按印 → 可否决），要有记录、在地平线留痕，不配发生在瞬态浮层里。需要第二个动作就必须升格 stage。

承接纪律：**位之间流动的是对象，不是消息**——peek 瞥见的选题卡升格 stage 时是同一个对象（引用传递），不是复制一份内容；"在一个项目上继续干" = 状态恢复，不是重开话题。

## 5. 地平线仪器条（新零件）

工作台的脊柱仪器，所有常驻物钉在这一条线上，桌面本身永远干净。**列表不常驻，入口常驻**：

```
[05-20 09:12 ●—●—●—○—○]      echo: editor.replace_range(para_3) ✓      [今日 ▾] [会话 ◔] [器物 ⊞]   ctx: desk · idle
```

- 左端**时间刻度**：节点点时间线，往回拨 = 会话回溯（会话 = 时间上的任务）；
- 中间 **echo**：当前命令回显（语义化动作，不是 CLI 风格）；
- 右端**入口三枚**：今日（语境指示器+切换）、会话、器物架（目录/素材）——点击从地平线 peek 出，用完收回；
- 右端 **ctx 读数**：当前语境。

它同时补上被删除的 mission-board（主仓 `HomeChatThread.vue` 已清理）腾出的任务状态位。

## 6. 环境生命感：窑变 / 天光 / 开片（不做神经网络）

神经网络/粒子流是 AI 产品第一俗套，且违反 token 文件的"静默优先"原则。译宝的差异化资产是**天青瓷**——让瓷器活起来：

- **天光**：石面桌底色温随真实时间极缓变化（晨冷白、午暖、夜深）。零噪声，陪伴感来自"它和你过同一个天"。纯 CSS。
- **窑变微光**：仅 think/work 状态，团子周围瓷面晕开极慢的釉变（`--yb-think-mist` 的审美升级，≤8% 不透明度），状态结束沉淀回平静。**脑活动 = 窑火。**
- **开片过场**：表面诞生时不滑入，而是**从桌面开片结晶**——一道细裂纹闪过、瓷片浮现，裂纹收拢成牵引线。一次性、有事件含义。
- **地平线脉冲**：后台事件落账时对应节点轻亮一下。动的是"信息到达"本身。

实现约束（硬性）：动效必须携带信息；循环动效仅 think/work 态激活；窗口失焦/遮挡即停；`prefers-reduced-motion` 直接关闭。

## 7. 语义色纪律（与 tokens.css 一致）

天青 `#4D90C4` = agent 注意力/选中；琥珀 `#F2A03C` = 待你定（含截止紧迫）；红 `#E5484D` = **仅**不可逆外发；绿 `#3E8E5A` = 完成。禁止紫色（通用 agent 指纹）。

## 8. 尺寸预算与降级规则（1440×900 基准）

| 区域 | 宽度 | 说明 |
|---|---|---|
| 对话区（日题+溪+溪口） | ~620px / 44–46% | 主角。气泡 max-width 380–420px（阅读行长 25–35 字），输入框 460–520px，多行向上生长至 3 行 |
| 今日枢轴 | ~380px / 27% | 周视图条 + 当日议程 |
| 器物架 | ~340px / 24% | 单列 masonry，2–3 张瓷片 |
| 地平线 | 28px 高 | 常驻 |

规则：

- **区宽呼吸，行长固定**：加宽的是区不是气泡，多出来的是"气"。
- **降级顺序**：<1280 器物架收成地平线"器物"入口的 peek；<1100 今日收成周视图条；对话区保底 420px。最后剩下的就是"它"和"你"。
- **新 token**：display 字阶两档（32/48，仅日题与任务题名等"空间题字"）+ serif 字族（Songti SC / Noto Serif SC，日题与文档正文）。

## 9. 故事线状态机（九幕 → 七态）

```
[S0 守夜]      reminders 触发 → agents 后台跑；仅地平线记账，零表面
  ▼ 用户:「把上周的工作写成周刊」
[S1 装配]      surface.open(notes_rail, peek) → 裁决: peek ✓
  │ 事件: notes.tag(card, excluded) ← 用户划卡（手势 = tool 调用）
  ▼ 用户:「开始写吧」（明确意图）
[S2 写作 stage] 裁决放行 stage；editor 原语挂载；对话转为锚定批注
  │ 事件: selection.changed → 对象模型
  │ 调用: zimeiti.rewrite(selection) → diff 原语 peek（琥珀"待你定"）
  │ 调用: editor.replace_range(...) ← 用户点接受 / agent 自拟，同一入口
  ▼
[S3 核查]      editor.get_document → 抽取事实声明 → coding.verify
  │ 不符 → inline 标注（琥珀波浪线）+ peek 对比卡，不静默改写
  ▼
[S4 配图排版]  图像 skill 产物进素材轨；拖拽封面 = editor.insert_image(card_id)
  ▼
[S5 钤印]      wewrite.publish = L3 闸门；agent 停在边界，红色发布印待本人确认
  ▼
[S6 散场]      表面层回收所有器；任务轨迹入地平线；reminders 设回访 → 回家态
```

校验规则：**图里说不出对应事件/tool 的元素就是装饰，删**。

## 10. 落地路径：第五套 preset（基于 Home 装配机制探查，08-28）

探查结论（详见探索摘要）：四级表面编排**已存在**（HomeWindow 的 `Presentation` + `deskWork/workBody` 通路，插件面板靠 CSS 变量定位盖进中央区）；布局是**数据驱动的 preset 体系**（`desktop/src/lib/assembly/presets.ts` 的 HOME_PRESETS：rails/desk/salon/canvas）；复用路径清晰（`useChatFlow` 会话引擎 UI 无关、`Bubble.vue` 独立、widget 瓷片现成）。

**方案：新增第五套并行 preset `field`（溪场）+ 新壳组件包住 HomeChat。**

- preset 管**静态摊法**（对话区 46% / 今日枢轴 / 器物架），呼吸管**运行时相位**（Presentation 编排叠在 preset 之上），两者正交；
- 呼吸策略作为 preset 的可选属性：field 预设下 stage = 对话收成锚定批注；老预设下维持现状——**老四套是逃生口**，新视觉长熟后再谈收编；
- 新增成本（最低档）：`presets.ts` 加一条数据 + `parts.ts` 登记新零件（日题、地平线）+ `homeAssemblyUi.ts` 的 PART_VIEWS 加映射 + HomeChat 加两个 slot；
- 地平线作为壳级贴底兄弟节点（先例：`.host-ask-slot`，`HomeChat.vue:862`），不进装配体系；
- stage 的"器占中央"直接沿用 deskWork/workBody 通路（HomeDeskWork 模式），无需新机制。

### 分期

- **P0 · 地平线 HorizonBar**：数据源全有（时间节点←feed 事件，echo←`sessionStatus` emit，今日/会话/器物←现有 widget）。低风险，先做。
- **P1 · 家态 field preset**：对话区 46% + 今日枢轴 + 器物单列 + 日题零件 + display/serif token + 天光背景（纯 CSS）。
- **P2 · stage 锚定批注**：最重，依赖宿主编辑器原语（zimeiti editor.html 提升）+ 对象模型（选区/锚点，需 api.toml `[[event]]` 事件通道落地）。**单独立项**。
- **P3 · focus**：stage 成立后的自然延伸，隐藏区域而已。
- **窑变/开片动效**：纯 CSS/过渡，P1 后随时可加，不挡主线。

### 1:1 视觉复刻的材料盘点

生图风格 = 你们已有的「天青瓷」finish（Soft UI / Neumorphism 2.0 方向）。绝大部分材料已在 tokens.css：石面桌/颗粒/厚瓷片/釉面/多层影/语义色/团子 Avatar。**缺口清单**：HorizonBar、日题零件、display 字阶、serif 字族、tether 牵引线样式、批注气泡变体、瓷片深度变量（`--depth`）、窑变动画、开片 keyframes。

验证方式：实现前先做**静态 HTML 小样**（单文件吃 tokens.css，1440×900 真实尺寸摆家态），与生图并排比对，像素级校准后再进 Vue。

## 11. 开放问题

1. **裁决器前后端分工**：agent 经 tool 操作表面层后，policy 引擎在 sidecar 还是前端？（初步倾向：不变量在 sidecar，呈现细节在前端。）
2. **任务轨一等公民**：任务轨迹若可回放/分叉/复用为模板，它本身应是一个器。涉及工作台的记忆与复用机制。
3. **原语清单边界**：哪些器配进宿主？标准：被 ≥2 个任务域需要的重交互组件才提升。
4. **老四套 preset 的终局**：field 成熟后，rails/desk/salon/canvas 是保留为"家态摆法"偏好，还是退役？倾向后者 + 逃生口收进设置。
5. **右侧栏"本次"卡**（`CapabilityConversationRail.vue`）与被删的 mission-board 语义重复，待任务轨设计时统一处理。

## 12. 视觉方向（故事板生图）

主基调：陪伴式「天青瓷」——石面桌 + 厚瓷片器 + 对话溪 + 团子在场 + 地平线仪器条。
已定调三态：家态（对话区 46% + 日题 + 今日枢轴 + 器物架）、stage（锚定批注版）、focus（阅读室）。
待出：守夜（深色）、装配（peek）、核查特写、配图、钤印、散场、agent 视野对开图。
