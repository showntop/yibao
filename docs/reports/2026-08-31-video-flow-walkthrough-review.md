# 视频创作 case 走查 review：「做一个关于如何赚钱的短视频」

> 日期：2026-08-31
> 方式：真机走查（worktree dev 实例，隔离数据目录）+ 代码机制核对。
> 任务输入：「做一个关于如何赚钱的短视频」，随后「打开我看一」「把这个选题立项成一个项目」。
> 结论一句话：**V1a 的零件都造出来了，但"流程"不存在**——选题确认、按印、立项相变在界面上全部不可达或不可见，用户看到的是 agent 一口气自转 + 面板乱弹。

## 0. 走查时间线（证据）

| 步 | 操作 | 实际发生 | 设计预期（video-creation-workflow §3/§6） |
|---|---|---|---|
| 1 | 「做一个关于如何赚钱的短视频」 | agent 直接 `zimeiti.add` 立了**一个**选题 + 直接写完 60s 口播稿 v1，全程 182s 无中断 | S0 应出 **3 个候选** inline 卡（带 HKRR/封面概念）→ 人挑 → 才立项 |
| 2 | 「打开我看一」 | agent 调 `zimeiti.open_editor`；**素材库浮层自动弹出**（用户没点任何东西） | 用户点名的东西才该开；开哪个器由裁决器按意图定 |
| 3 | 素材库浮层点「查看」/点选题标题 | **无任何反应** | 应打开选题详情卡（detail.schema.json，含 HKRR + 立项按钮） |
| 4 | 对话流点「摊开 选题名」 | stage 面占了对话区，标题「内容创作」，**内容为空**（"这里还空空的"），对话被盖住 | 摊开应带着对象（那条选题）进 stage，不是开一张空看板 |
| 5 | 「把这个选题立项成一个项目」 | agent 正确调 `project.create`，**L3 闸门触发**（sidecar 日志：等待用户确认） | 按印卡出现在对话流，人按印 |
| 6 | 找闸门卡 | 大窗只有「收件箱 等你确认 1 项」toast（点击=navigate('home') 原地踏步）+「主屏」tab 徽标 ①（已在该 tab）。**对话流里没有闸门卡**；小窗团子只显示发呆，确认卡不可见 | —— |
| 7 | 译宝面板窗（780×580） | 也开着一份「素材库」，但**空的**；浮层那份有数据。**同一器两个实例，数据不一致** | 器全库只有一份 |

## 1. 阻断级问题（流程走不通）

### B1 大窗里 L3 确认不可达（最严重）
- 机制：PendingConfirmCard 只长在**小窗** chat 视图（PetWindow.vue:919，且替换输入条）；大窗的唯一入口是 ActivityShelf 的 toast，其 handler 是 `navigate('home')`——原地跳转（HomeWindow.vue:609）。设计中的大窗收件箱 FeedInbox **没有任何地方挂载**（HomeFeed.vue 已是死代码，只剩注释引用）。
- 又：大窗对话与宠物窗共享 `surface="pet"`（HomeChat.vue:547），所以确认发给了 pet 面，大窗只剩徽章。
- 结果：在大窗发起任何需要按印的操作（立项、发布）= 死等。用户报"审批没有显示出来"即此。
- 方向：按印卡作为**对话流内联卡**落在发起会话里（这正是设计纪律"L2/L3 按印永远回落对话流闸门卡"的实现缺口）；toast 点击应定位到那张卡，而不是 navigate('home')。

### B2 摊开 = 空容器（对象不承接）
- 「摊开 选题」打开的是插件面板**壳**，数据没装载（或装载失败显示空态）。stage 面还把对话流整个盖住——闸门卡来时正好被它挡死。
- 机制：摊开只传了"打开哪个面板"，没传"打开哪个对象"；panel 的 init 数据推送在窗口已开时还会丢（show_panel_window_impl 的注释自己承认了 panel-shown 重推这个补丁，但仍然漏）。
- 方向：摊开必须携带对象引用（topic id），面板以对象为中心渲染；空态不该出现"有数据却显示空"。

### B3 选题详情卡没有可达路径
- detail.schema.json（含 HKRR 四行 + 立项按钮）已实装，但素材库浮层的「查看」（`zimeiti.mat_get`）点了没反应；看板里点选题也无响应。= V1a 的「立项」按钮用户根本摸不到。
- 注：素材库的「查看」调的是 `mat_get`（素材域），选题详情在 board 的「详情」（`zimeiti.get`）——**素材与选题两个域在 UI 上长得一样、行为不同**，用户无法分辨。

## 2. 机制级问题（逻辑不清晰之根）

### M1 没有"流程"，只有工具
「做短视频」的预期是 S0 选题（3 候选+HKRR+封面前置）→ 立项 → S1 脚本。现实是 agent 一次 run 里 `zimeiti.add`（无闸门）+ 写稿全做完。**候选-确认环节不存在**：topics skill 的"四件套"只是 prompt 建议，没有任何机制强制"先给候选、等人挑"。
- 方向：选题需要状态机意义上的阶段（候选→候选确认→立项），不能只靠 LLM 自觉。`zimeiti.add` 直接立选题进库这个动作在视频流程里应该只能产"候选"，立项必须经过人。

### M2 peek/inline/浮窗的弹出没有裁决
- 现实规则：tool 声明了 `panel = "zimeiti:xxx"` → 工具结果产生 panel 事件 → **braind 兜底 force-show 面板窗**（braind.rs:296 注释：不论前端裁决与否都弹）。所以"什么时候 peek 什么时候 inline"的答案是"tool 写死了 + Rust 兜底乱弹"，用户当然感觉没逻辑。
- 用户说"打开我看一"想看的是**稿子**（编辑器），弹出来的却是**素材库**——open_editor 的 panel 事件与素材库事件混着弹。
- 方向：surface-policy 裁决要真实存在：只有"用户当前意图指向的对象"才允许上浮层；tool 的 panel 绑定只是"能力声明"，不是"弹出指令"。

### M3 器多实例、数据不一致
素材库同时存在于：浮层 peek（有数据）、译宝面板窗（空）、stage 摊开（空）。设计说"全库只有一份器"。面板窗的 init 数据推送丢失是老问题（代码注释里的补丁也没修好）。

## 3. 交互级问题

- **I1 对话流不自动滚到最新**：surface 收起后，最新消息（含我的立项请求）在视口外，滚轮在对话区不生效（滚动容器没吃到事件）。新消息不可见 = agent 说了什么用户不知道。
- **I2 「摊开」链接成堆且语义不明**：一轮对话里 3 条「摊开 内容创作」+ 2 条「摊开 <选题名>」，长得一样、去向一样（空看板）。用户问"不知道为什么会到这里"。
- **I3 工具卡暴露内部名**：`zimeiti.add 详情`、`保存稿件 详情`、`zimeiti.open_editor 详情`——工具 id 直接上桌。"详情"点开是什么没有预期。
- **I4 toast/徽标都是死按钮**：收件箱 toast 原地跳，主屏徽标在当前 tab 上无意义。待批准状态的引导等于零。
- **I5 小窗确认卡发现性差**：确认卡只在小窗 chat 视图替换输入条；小窗收起时只有团子在发呆，无任何"有事等你"的外露信号（团子没有琥珀态）。

## 4. 视觉/信息结构问题

- **V1 每条消息挂 token/耗时/模型名**（39,152 tokens · 182.3s · deepseek-v4-flash）：创作流程里这是开发者噪音，应收进调试开关。
- **V2 「参考了 1 项」语义模糊**：参考了什么、跟正文什么关系，无从知晓。
- **V3 信息层级混乱**：对话流、浮层 peek、stage 空壳、日历、技能 chips、收件箱 toast 同时抢视线；一个任务（做视频）的"现在进行到哪一步"没有任何地方回答。地平线 ctx 全程 `home · idle`——任务在进行中也没变（run 时才变 work，结束回落，没有"项目/阶段"语义）。
- **V4 项目卡不可见**：只在 field 预设 shelf；默认 rails 预设没有。且立项没完成前也无从验证。
- **V5 技能 chips（日程/写作/生活/智能体调度/编码）与当前任务无关**：做视频时没有"视频创作"入口，全靠自然语言碰运气。

## 5. 与设计文档的差距对照

| 设计（已定稿口径） | 现状 |
|---|---|
| S0：3 候选 inline 卡 → peek 比较 → 立项相变 | agent 直立 1 个选题直写稿；详情卡不可达；立项按钮摸不到 |
| peek 纪律：看 + 一个决定 | peek 自己乱弹（非用户意图），且里面什么决定都做不了（查看是死的） |
| L2/L3 按印回落对话流闸门卡 | 闸门触发正常（sidecar 日志为证），但卡不在对话流，大窗不可达 |
| 承接靠对象传递 | 摊开不传对象，开空壳 |
| 器全库一份 | 素材库三份，数据还不一致 |
| 地平线 ctx 读项目/阶段 | 全程 home · idle |

## 6. 做得对的（别改回去）

- 立项意图 → agent 正确路由到 `project.create` 且 **L3 闸门确实拦住了**（日志：等待用户确认）——工具分级与闸门机制本身工作正常。
- 崩溃修复后 dev 实例长时间稳定。
- sidecar/desktop 测试全绿（除两个既有失败）。

## 7. 修复优先级建议

1. **B1 按印卡进对话流**（不解决，一切 L3 流程都死）：确认卡作为会话内联卡 + toast 点击定位到卡。
2. **M2 弹出裁决**：摘掉 braind force-show 兜底，panel 事件经前端裁决器按"当前意图"决定 inline/peek/不弹。
3. **B2 摊开带对象 + 面板 init 数据修复**。
4. **M1 选题候选环节**：视频意图 → 强制先出候选（工具层加"候选"状态或直接在前台流程里拆步），立项才调 project.create。
5. **I1 滚动/I3 工具卡文案/V1 token 噪音**等表层打磨。
6. B3 素材/选题两域的入口梳理（随 M2 一起）。
