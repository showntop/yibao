**观察（供 Slice 2 排查，不下结论）：**

1. SoM 仅有的 2 个命中中心距恰为 0.0（正中靶心），疑似走了 a11y 解析而非像素预测；同为易档的 sysset 两场景却全 miss 且偏移 300+px——AX 解析路径在系统设置上可能没生效。
2. miss 的偏移量级普遍 100–870px，不是抖动级，疑似坐标系/尺度/归一化的系统性问题，而非模型精度问题。
3. baseline 在 5 个场景（集中盲/中档）完全无有效预测输出。
4. GLM 返回原始坐标见 `.superpowers/sdd/slice1-click.txt`，复查时先对照场景 PNG 与 `gt.rect` 验证坐标空间假设（本机 scale=1.0，与采集机一致）。

## 5. Slice 2 修复清单（由本报告导出）

按 spec，红项即 Slice 2 修复对象：

1. **点击 grounding 系统性排查**（最高优先）：先验证坐标空间假设（GLM 归一化坐标 ↔ scale=1.0 ↔ gt 逻辑坐标），再查 SoM 的 a11y 解析为何只在计算器生效。目标：易档 100%、盲档 ≥80% 且中位距 ≤20px。
2. **edge TTS 延迟**：实测 1.14–1.29s vs 线 1.0s。两条路：排查网络/端点（换 region、测纯 API 延迟拆分合成与传输），或重新校准达标线（需改 spec，走用户决策）。
3. **TTS 云/本地补配后补验**：dashscope key、本地模型+依赖——配置到位后跑 `eval_tts.py` 补齐三引擎基线。

遗留功能三项（watch 跨重启恢复/深色模式/截图唤起）与误报反馈回路按 spec 原计划在 Slice 2 照常进行，不受本报告影响。
