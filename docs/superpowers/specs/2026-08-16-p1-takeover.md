# P1 接管（总线型 Handoff）——coding 面板输入条接管 spec

日期：2026-08-16 ｜ 依据：docs/research/2026-08-16-yibao-collab-patterns.md（P1 模式）

## 背景与问题

coding 面板窗（PanelApp）里同时存在两个输入框：工作台条 InputBar（译宝大脑 GLM）与 iframe 内 chat.html 自带 textarea（Claude Code）。冗余且定位不清（用户原话「两个太怪了」）。

架构原则（用户拍板）：**译宝掌控全局（全知调度者），编码智能体是局部执行者；协作模式可复制到其它智能体**。全知靠事件 tap（生命周期+摘要），不靠当中间人。

## 目标

coding 面板在 PanelApp 打开时（`current.panel === "coding:chat"`）：

1. 面板窗内只剩一个文本输入框（工作台条 InputBar），文本直送编码智能体
2. iframe（chat.html）隐藏自己的 textarea + 发送钮，保留全部编码控件：消息流/工具卡/审批卡/run pill/错误条/cwd chip/权限 pill/历史/新对话/handoff/stop
3. iframe 状态（提交中/运行中/等审批/空闲）实时上报 → 驱动团子 avatar 状态 + reportPanelContext 注入译宝大脑上下文（零 sidecar 改动，复用 `_FOCUS` 通道）
4. 接管态视觉归属明确：placeholder 切换 + 接管回执（译宝对话浮层留一行「已转交编码智能体」，历史不双写）
5. @ 文件引用不失能：iframe ctx-row 的「@ 引用文件」变按钮开搜索浮层，选中后经桥插入 Vue InputBar 草稿

## 非目标（P1 不做）

- 审批上移到 PanelApp L2 确认条体系（→ P4/第二步）
- 其它 webview 面板的接管（机制通用化但只接 coding）
- 禁止 coding 被 PeekSurface/HomePlugins 打开——**不需要**：takeover 是 PanelApp 显式下传的 opt-in 标志，其它 surface 不传，iframe 保留自带输入框，行为与现状一致
- 语音输入接入编码（禁用态维持现状，不新增处理）

## 关键交互规则

- **排他**：takeover 时 InputBar 的 submit 全部路由 iframe，不进 runInput/不 pushMsg 用户行（防历史分裂）
- **排队语义**（Codex Queue 式）：编码 busy（sending/streaming）时 takeover-input 进 iframe 内队列，本轮结束后自动发送，status 提示「已排队，本轮结束后自动发送」
- **中断**：takeover 时 InputBar 屏蔽 stopping 语义（不触发 brain interrupt）；esc 由 PanelApp 监听转发 `takeover-stop`；iframe 内 stop 钮/run pill Stop 不变
- **IME 守卫**：Vue InputBar 补 compositionstart/end + 50ms 窗口（对齐 chat.html 既有实现，WebKit bug 165004）
- **接管结束**：切走/关闭面板 → InputBar 回归译宝大脑（现有逻辑零改动）

## 接口契约

### 桥（WebviewPanel.vue）
- iframe→父 事件：`{src:"yibao-webview", event:<name>, payload}`（无 id，onMessage 在 id 检查前分流，emit `panel-event`）
- 父→iframe 任意消息：WebviewPanel `defineExpose({ postToIframe(msg) })`，发 `{src:"yibao-host", ...msg}`（JSON 去 Proxy 同 replyToIframe）
- takeover 标志：新增 prop `takeover?: boolean`，随 init 载荷下发 `{src:"yibao-host", type:"init", data, takeover}`
- BRIDGE_JS 扩展：`yibao.onMessage(cb)`（init/invoke 响应之外的 host 消息）；`yibao.emitEvent(name, payload)`；init 回调签名扩展为 `(data, fullMsg)`

### 事件词汇（chat.html → PanelApp）
- `takeover-state` `{state: "sending"|"streaming"|"waiting"|"idle", session: boolean}`
- `insert-draft` `{text: string}`（@ 选中回输）

### 父→iframe 消息
- `{type:"takeover-input", text}` → busy 则排队，否则填 #prompt 调原 send()
- `{type:"takeover-stop"}` → 等价点 iframe 内 stop()

### InputBar.vue
- 新 props：`placeholder?: string`（默认现文案）、`takeover?: boolean`（屏蔽 stopping/interrupt 语义）
- 新 expose：`insertText(t)`（追加+draft 持久化+autoGrow+focus）
- IME 守卫：compositionstart/end + isComposing/lastCompEnd 50ms

### 译宝感知（PanelApp）
- takeover-state → avatar state（sending/streaming/waiting→"work"，idle→"idle"）
- takeover-state → `reportPanelContext({plugin:"coding", panel:"chat", item:{id, title:"编码对话（状态文案）", status:state}})`
- setCurrent 进入 coding 时对话浮层 pushMsg hint「编码智能体已接管输入条」

## 验收标准

A. coding 面板窗内只有一个可输入文本框；placeholder 显示「编码智能体接管中，直接说任务…」
B. InputBar 发送 → iframe 消息流正常出用户气泡+流式回复；中文输入法组字中 Enter 不误发
C. 运行中再发 → 排队提示 + 本轮结束自动发出
D. 运行中按 esc（焦点在输入条）→ 中断生效
E. cwd chip 浮层、权限 pill、审批卡、run pill、stop、历史恢复、新对话、handoff 在接管态全部照常
F. @ 按钮 → 搜索浮层 → 选中插入 InputBar 草稿（takeover）；非 takeover surface（大窗插件页/peek）@ 仍插入自身 textarea
G. 译宝大脑上下文可见编码状态（问「它现在什么状态」能答）
H. 非 coding 面板（notes/reminders/zimeiti）工作台条行为零变化
I. sidecar `uv run pytest -q` 全绿（无 sidecar 改动，回归兜底）
