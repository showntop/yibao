# 译宝活动回忆工具设计（2026-07-28）

## 0. 决策摘要

把“最近活动”接入译宝现有 tool-calling agent，而不是在壳侧用关键词猜测后自动注入。新增底座只读工具 `load_user_activity`：LLM 在用户问题确实需要活动上下文时，自行选择时间窗口并调用；工具读取本机加密感知库，构造有界的结构化时间线，再把结果交回当前模型。

由于当前默认模型是云端 GLM，解密后的活动上下文返回给模型属于新的数据出站点。新增独立设置 `perception.model_access`，默认关闭；只有用户明确开启后工具才允许返回活动内容。成功使用后，现有对话 UI 在最终回复下显示轻提示“已参考最近活动”。

## 1. 目标与边界

### 1.1 目标

- 支持“我刚才在干嘛”“今天主要在哪些应用里”“刚才切到哪个项目了”等问题。
- 让 LLM 根据自然语言和每轮已有的本地时间 system message 自行决定是否调用、查询哪个时间窗口。
- 复用现有 `SkillRegistry → ToolInvoker → AgentLoop` 工具链、风险闸门和事件流。
- 感知内容只在本轮模型调用与前端内存中短暂出现，不写入明文审计日志或持久化会话历史。
- 对用户明确披露：开启模型访问后，所选时间窗口内的应用名、窗口标题和活动状态会发送给当前模型服务。

### 1.2 非目标

- 不做截图、OCR、a11y 文本读取或剪贴板采集。
- 不做每轮自动注入，也不新增壳侧关键词意图判断器。
- 不做周报、使用时长统计、主动建议或 mem0 模式提炼。
- 不改变现有感知采集总开关；暂停采集不等于删除历史记录，已保留记录仍可在模型访问开关开启时被查询。
- 单次调用不查询超过 24 小时；更长区间由后续统计能力单独设计。

## 2. 为什么用工具

当前 `AgentLoop` 每一步都把可见工具 schema 交给 LLM；LLM 发出 tool call 后，`ToolInvoker` 完成风险判断、执行和审计，结果以 `role=tool` 回到下一步模型调用。`load_user_activity` 属于译宝认知底座，不属于某个业务插件，因此注册为始终可见的底座工具，不经过 `use_plugin` 展开。

记忆和面板焦点目前是每轮自动注入的例外。活动记录敏感、并非每轮都相关，若照此自动注入会扩大出站范围和 token 成本，所以改用模型按需加载。

## 3. 工具契约

### 3.1 名称与风险

- 工具 id：`load_user_activity`
- 展示标签：`加载活动记录`
- 风险：`L0_READONLY`
- 描述必须约束模型：只在用户询问过去活动、应用切换、当前工作上下文时调用；不得为了“让回答更个性化”而无关调用。

### 3.2 参数

```json
{
  "type": "object",
  "properties": {
    "start_at": {
      "type": "string",
      "description": "查询起点，本地时间 ISO 8601，例如 2026-07-28T13:00:00+08:00"
    },
    "end_at": {
      "type": "string",
      "description": "查询终点，本地时间 ISO 8601，例如 2026-07-28T14:00:00+08:00"
    }
  },
  "required": ["start_at", "end_at"]
}
```

规则：

- 起止时间必须带时区；解析后要求 `start_at < end_at`。
- `end_at` 不得晚于当前时间 5 分钟以上，容忍模型和系统时钟的小误差。
- 单次窗口最大 24 小时；超出时返回可纠正的人话错误，让模型缩小窗口后重试。
- 用户说“刚才”时模型通常取最近 30 分钟；“最近”取最近 60 分钟；“今天”取本地当天 00:00 至当前时间。它们写进工具描述作为路由提示，不在壳侧重复实现关键词规则。

### 3.3 返回结构

```json
{
  "window": {
    "start_at": "2026-07-28T13:00:00+08:00",
    "end_at": "2026-07-28T14:00:00+08:00"
  },
  "segments": [
    {
      "start_at": "2026-07-28T13:20:14+08:00",
      "end_at": "2026-07-28T13:35:02+08:00",
      "app": "Chrome",
      "title": "GitHub · yibao",
      "activity": "active"
    }
  ],
  "observation_count": 8,
  "truncated": false
}
```

- 查询先按明文时间索引筛选，再逐条解密 payload；数据库仍保持字段级加密。
- 每个来源额外读取窗口起点之前最近一条记录作为初始状态，但不把窗口外时间暴露给模型。
- 按时间正序合并 app/title 与 active/idle 状态；任一状态变化就结束上一段。
- 相邻状态完全相同的段合并；最多返回 120 段，超过时保留最近 120 段并置 `truncated=true`。
- 无记录返回成功空结果；存储/解密失败返回失败结果，LLM 必须如实说明无法读取，不得猜测活动。

## 4. 授权与透明度

新增运行期设置：

```text
perception.model_access = false
```

设置页在“感知”组增加子开关“允许模型读取感知记录”，默认关闭。说明文案：

> 开启后，译宝可在你询问最近活动时，把所选时间窗口内的应用名、窗口标题和活动状态发送给当前模型服务。不会发送截图或按键内容。

行为：

- 开关关闭：工具 schema 仍可见，但 `precheck` 在读取前拦截，返回“模型读取感知记录未开启”；这样 LLM 能解释如何开启，而不是假装没有记录。
- 开关开启：工具可自动执行，不再逐次弹确认；用户已经在设置中给出持续授权。
- 感知存储不可用：工具不注册，避免模型反复调用一个永远失败的能力。
- 成功返回至少一段活动后，本轮最终回复之后发送现有 `notice` 事件：“已参考最近活动”。四个现有对话表面沿用已有 notice 样式，无需新增 UI 协议。
- 空结果不显示“已参考最近活动”，避免暗示模型拿到了事实。

## 5. 敏感数据持久化边界

现有工具结果默认会进入 `audit.db`，完整工具轨迹还会进入 `history.json`。直接复用会把解密后的窗口标题重新明文落盘，因此 `load_user_activity` 必须声明敏感输出，并经过以下收口：

- **模型往返**：本轮内使用完整结构化结果，这是用户开启模型访问后允许的出站点。
- **审计日志**：只记录工具 id、时间窗口、成功状态、`observation_count`、`segment_count` 与 `truncated`；不记录 app/title/activity 内容。
- **会话历史**：保留 user 问题、工具调用名和安全摘要“已加载 N 条活动”；工具完整结果不落盘，最终回答替换为“【本轮使用感知记录回答，敏感内容未写入会话历史】”。
- **前端**：`action_result` 事件只携带安全摘要，因此现有过程详情只能展开看到时间窗口、条数与截断状态；完整活动只进入本轮模型消息，不进入壳事件流。
- **长期记忆**：本轮活动详情不写入 mem0。现有 `memory.add(user_text)` 只存用户原问题，不加入工具结果或回答内容，保持不变。

为避免给单个工具写旁路，`Skill` 增加通用的敏感输出声明与安全结果接口；默认工具保持现状，只有声明敏感输出的工具在审计、历史和前端事件中使用安全结果。安全结果钩子自身若异常，底座必须 fail-closed 为仅含 `redacted=true` 的摘要，禁止回退完整结果。

## 6. 组件改动

### 6.1 `perception.py`

- `PerceptionStore.query_window(start_ts, end_ts, limit)`：按时间窗口查询并解密，返回正序观察。
- `PerceptionStore.latest_before(source, ts)`：为 app/activity 各取窗口前最近状态。
- `build_activity_segments(...)`：纯函数合并状态变化，便于不依赖 Keychain/SQLite 的单元测试。
- `RecallActivitySkill`：参数校验、授权 precheck、窗口查询、结构化返回和安全持久化摘要。

### 6.2 `skills.py` / `invoker.py` / `loop.py`

- `Skill` 增加默认关闭的敏感输出能力与 `safe_result` 钩子。
- `ToolInvoker` 写审计前调用技能的 `safe_result`；普通工具默认原样返回。
- `AgentLoop` 给模型使用完整结果，给壳侧 `action_result` 和 `ConversationHistory` 使用安全结果；若本轮成功取得非空活动，在 `final_reply` 后追加 notice。
- 同步 `run` 与异步 `arun` 行为一致，防止 CLI/测试路径和桌面路径分叉。

### 6.3 `server.py` / `config.py`

- 在感知存储成功创建后把 `RecallActivitySkill` 注册到 `agent.skills`，共享同一个 `PerceptionStore` 实例和实时 settings 字典。
- 新增 `perception.model_access` 已知设置键，默认 `false`，沿用现有 `settings_set` 即时生效机制。

### 6.4 设置页

- `SettingsView.vue` 增加模型访问开关及明确出站说明。
- 开关不依赖当前采集开关的开/关状态：用户可以暂停采集但仍允许模型读取尚未删除的历史记录。
- 现有 notice 渲染即满足“已参考最近活动”，不新增事件类型或专用组件。

## 7. 错误处理

- 时间格式错误、区间反向、未来过多、超过 24 小时：返回确定性参数错误，允许 LLM 修正后重试。
- 授权关闭：precheck 阻止读取，不触碰解密存储。
- 单条历史 payload 损坏：跳过该条并继续构建；若全部不可用则返回空结果并带 `skipped_count`。
- Keychain/数据库整体不可用：不注册工具，感知采样仍按现有 fail-closed 逻辑关闭。
- 模型调用失败：工具结果只存在本轮内存；失败不会导致敏感结果落入审计或历史。

## 8. 测试与验收

### 8.1 自动测试

- Store：时间窗口边界、正序、窗口前种子、坏 payload 跳过。
- Builder：app 切换、active/idle 切换、相邻合并、无种子、120 段截断。
- Tool：schema、默认关闭 precheck、即时开关、ISO/24h 校验、空结果、结构化结果。
- 隐私：审计库不含 app/title；history 文件不含 app/title 和最终回答敏感文本；LLM 当轮确实收到完整工具结果。
- Agent loop：LLM 不调用时零读取；调用成功且非空时最终回复后有“已参考最近活动”；空结果/失败不显示提示；同步和异步路径一致。
- Server/settings：真实构建路径注册工具、存储不可用时不注册、设置持久化。
- 前端：TypeScript 与 production build；设置开关沿用现有 settings 测试路径和手测。

### 8.2 真机验收

1. 默认关闭模型访问，询问“我刚才在干嘛”：译宝说明需要在设置开启，不读取记录。
2. 开启后切换三个应用，等待采样，再问同一问题：工具过程显示“加载活动记录”，回答顺序与窗口标题基本一致。
3. 最终回复下出现“已参考最近活动”。
4. 检查 `audit.db` 与 `history.json`，确认不存在测试窗口标题明文。
5. 暂停采集但保留历史，再次询问：仍可读取已有记录；清空感知日志后返回无记录。

## 9. 已决取舍

- 工具名使用 `load_user_activity`：`load` 明确表达按需加载，单数 `activity` 表示一段连续的用户活动时间线，避免复数 `activities` 被模型误解为待办或活动列表。
- LLM 决定是否加载及时间窗口，壳侧不做重复意图识别。
- 模型访问授权独立、默认关闭；开启后不逐次确认。
- 本轮完整活动可以发送给当前模型，但不得以明文进入审计、会话历史或长期记忆。
- v1 只返回 A/C 源结构化时间线；截图与内容理解继续留在感知 v2。
