# 小窗能力表面设计（2026-08-13）

> **一句话：** 让 Phase 1 建好的能力表面模型触达小窗——把「面板 = 弹独立浮窗」换成**给已有的过程行补一个表面属性**，并补上声明式插件表达表面建议的渠道。
>
> **上位 spec：** `docs/superpowers/specs/2026-08-13-pet-os-mainline-design.md` §3 Phase 1.5
> **设计依据：** `docs/research/2026-08-09-capability-surfaces-design.md` §5（Inline）、§12.7（presentation 是建议非命令）、§16（反模式：多个自由漂浮面板）

---

## 1. 为什么

Phase 1 落地了裁决器、Inline 回执、Peek 探窗、活动轨，四道闸门全绿，但真机验收条 ①「记一下这句话」只出 Inline 不开面板」在**大窗小窗都不成立**。两个成因互相独立。

**缺口 A · 声明式插件没有声明渠道。** Phase 1 把 `presentation`/`attention` 加在 `ActionResult` 上，只惠及代码式 Skill。`plugins.py` 全程未解析这两个字段，`DeclarativeTool` 返回的 `ActionResult` 恒为默认值。而 notes、reminders 这批最该走 Inline 的轻量插件**全是声明式的**——`notes.keep` 在 manifest 里只有 `panel = "notes:list"`。于是大窗实际走：`suggested=null` → 回落 `stage` → 非 explicit 封顶 → 开 **Peek**，不是 Inline。

**缺口 B · 小窗未接裁决器。** 裁决器只接进了 `Home.vue`/`HomePlugins.vue`。`App.vue:727-738` 的 `case "panel"` 仍是无条件 `openPanel()`（`invoke("open_panel_window")`，独立 Tauri 窗口）外加宠物窗收回球形态。这比大窗的 Stage 更重，且正是调研 §16 列为反模式的「多个自由漂浮面板制造窗口管理负担」。而小窗是桌宠常驻主入口，「记一下这句话」这类轻量动作多数就发生在这里。

> **范围澄清：** 仓库有五处 `case "panel"`，只有 `App.vue` 是缺口。`PanelApp.vue` 是浮窗内部的内容渲染器（`setCurrent` 填 payload，不决定开窗）；`HomeChat.vue` 仅维护「⇢ 协作」关联气泡且注释已明确「不主动抢页面」；`CapabilityConversationRail.vue` 仅 push 一条活动行；`HomePlugins.vue` 已接裁决。四者职责各异，**不抽共享 `useBrainSurface` 层**——那会把职责不同的代码强行归一，造出错误的抽象。

## 2. 进度与表面是一行的两个正交属性

小窗的物理形态是宠物球加可展开对话框（收起 320×300，展开 `lib.rs:82-113` 定为 **360×520**），**没有 Stage/Focus 的空间概念**，不能套用大窗四档。

小窗对话流里本就有**过程行**：`action_proposed` 时 push 一条 `{role:"sys", text: procLabel(action), pstate:"run"}`，`action_result` 时收尾为 `记闪念 ✓`（`App.vue:558-576`）。若面板事件再另起一条痕迹，同一个动作在流里占两条，且文案重复——`记闪念 ✓` 与「已记录」说的是同一句话。

**但它们不是同一件事的两段，而是正交的两个维度。** 过程行回答「它正在做什么、做完没有」，是**动作的状态**；痕迹回答「这里有个表面可以打开」，是**结果的可达性**。三种组合都真实存在：

| | 无面板 | 有面板 |
|---|---|---|
| **有动作** | `memory.save`、`tts.speak` | `notes.keep`、`notes.list` |
| **无动作** | —— | 插件视图直调、插件后台 `emit_event` 推面板 |

因此「把过程行升级成痕迹」这类锚定方案是**有缺陷的**：第三种组合没有锚可用，必须回退新增。需要例外分支，说明抽象没找对。

**正确的模型：一行 = 一个动作，这行有进度与表面两个独立属性。** 面板事件不「升级」某一行，只是给它补上表面属性；按 `origin`（发起动作 id）找不到对应行时，新建一行、只有表面属性没有进度属性。没有例外分支，只有「找得到就补，找不到就建」。

`origin` 的语义也因此更准确：不是「锚定到过程行」，而是**「这个面板属于哪个动作」**。

### 2.1 小窗只有行，没有卡

顺着上面的抽象推下去，卡站不住。

文案上，运行中用户关心「它在干嘛」，完成后关心「我能看什么」，所以同一行的文案自然从动作名演进成面板名——这是一行随时间变化，不是两行并列。

那卡还剩什么？相对于一条可点的行，它只多了一个更大的视觉块和一个「展开」按钮，而点击整行本来就能展开。它并不承载撤销——`InlineReceipt.vue:31` 的两个动作是「忽略」和「展开」，**没有撤销**。再加上小窗只有 360px 宽，卡（`min-width: 260px` 三段式）会顶满、文案区仅剩约 150px 必被 ellipsis 截断。**多占一大块空间，多提供的信息接近于零。**

于是一个组件渲染五种状态：

| 状态 | 呈现 |
|---|---|
| 运行中 | `记闪念 ⟳` |
| 失败 | `记闪念 ✗ 表未找到` |
| 成功 · 无面板 | `记闪念 ✓` |
| 成功 · 有面板 · 最新 | `闪念列表 · 13 条 ›`（accent，可点 → explicit → 开浮窗） |
| 成功 · 有面板 · 被取代 | `闪念列表 · 13 条`（`--yb-text-faint`，不可点） |

**有面板的行不再显示 ✓。** 失败结果本就不带表面建议（见 §5），所以「有表面」已蕴含「成功了」，图标是冗余的。

新面板事件到达时，此前所有带表面属性的行一律降为不可点——流里**永远最多一条是可操作的**。

**大窗小窗形态不一致是正确的，不是缺陷。** 两者本就不一致：大窗有 Stage/Focus/Peek，小窗一个都没有。能力表面模型要求一致的是**裁决逻辑**，不是**呈现形态**——宿主按自己的空间决定怎么落地，这正是这套模型存在的理由。大窗保留 Phase 1 的 `InlineReceipt` / `PeekSurface` / `ActivityShelf`，本阶段一律不动。

### 2.2 计数

取 `data.rows?.length`，取不到就只显示面板名。`plugins.py:211` 的 db query 恒返回 `data={"rows": rows}`，panel 事件本就透传 `data`，**零协议改动**。但这只对 db 类声明式工具成立，http 工具与代码技能的 `data` 形状不保证——因此计数不得写进任何断言，缺失是正常降级路径。

### 2.3 开窗动作不需要携带面板身份

行的点击动作是：置 explicit 标志后 `openPanel()`。

**它不需要记住自己对应哪个面板。** 因为可操作的行永远是最新那条，而浮窗内容渲染器（`PanelApp.vue` 的 `case "panel"` → `setCurrent`）本就跟着最新面板事件走——两者天然指向同一个面板。

这条性质直接消掉了 Phase 1 里 `peekPanel` 那类「面板 A 的标题配上面板 B 的内容」的错位 bug 的**整个可能性**，而不是靠再打一次快照去躲。「只有最新一条可点」这个约束的收益不止于克制，也在于此。

### 2.4 为什么旧行不可点

「统一可回溯」的准确边界是：**可回溯的是「发生过什么」，不是「回到那一刻」**。

旧行若可点，等价于在对话流里散落一堆入口，正是 §16 要避免的窗口管理负担的变体。而「回到闪念列表」永远有路——小窗本就有插件视图（`PetView = "chat" | "plugins"`，`App.vue:1112` 切换钮，`launchPlugin` 直调 `{id}.list`）。

于是职责清晰分离：**历史归对话流，导航归插件视图。**

这一决定同时避开了两个坑：不必为旧痕迹存快照数据（对话流不会变成数据坟场，也不与 Phase 2 TaskTimeline 的权威存储职责冲突），也不必重放工具动作（不触碰 Phase 2「恢复只重建 UI 呈现，不重放工具/模型动作」的硬约束）。

## 3. 小窗表面映射：`decideSurface` 原样够用

**不需要给裁决器加 `autoMax` 入参**（Phase 1.5 初版计划中的该任务作废）。既然小窗只有行一种形态，映射塌缩成**二值**：

| `decideSurface` 输出 | 小窗 |
|---|---|
| `stage` / `focus`（且 `show`） | 直接开浮窗（`openPanel()` + 收回球形态） |
| 其余一切（`inline` / `peek` / `show=false`） | 行 |

`inline` 与 `peek` 在小窗不再有形态差别——它们的区别原本就只体现在呈现密度上，而密度统一之后，剩下的唯一区别是「是否允许开窗」，那由 explicit 决定、不由 `presentation` 决定。`presentation` 仍然有用：它是 `decideSurface` 判断该不该升到 `stage` 的输入。

**开窗与留痕不互斥：两者都发生。** 表面属性先补到发起它的那一行上，再决定要不要开窗——所以即便直接开了浮窗，流里同样留下一条可点行，用户关窗后仍能一键回去。这样「每个面板事件都在流里留痕」没有例外，代码里也少一个分支。

关键性质：裁决器在非 explicit 时**本就封顶到 `peek`**（`surface-policy.ts:11` 的 `AUTO_MAX`），所以 `stage`/`focus` 只可能在 explicit 时出现——**「模型自动调用绝不在小窗开浮窗」这条硬规则自动成立**，无需额外代码。

`attention=quiet` 与「`stage` 非 explicit」在小窗合流为同一条行。这是有意简化：小窗只有行一种形态，两者本来就没有可区分的表现。

## 4. explicit 的三个来源，全在前端

前端本就看得见用户输入文本，也有 `loadPlugins()` 拿到的插件名列表，因此**无需协议加 `explicit` 字段**。三个来源统一置同一个时间窗标志，`case "panel"` 复用 `HomePlugins.vue:321` 同构的判断（`requestedPlugin === plugin && Date.now() <= requestedUntil`）：

1. **插件视图点击**（`App.vue:449-456` `launchPlugin`）——**这是回归修复**：接上裁决器后若不置标志，点插件将开不了窗，而今天它能开纯粹因为 `case "panel"` 无条件开窗
2. **可点行的点击**
3. **窄规则文本匹配**——用户消息命中「打开/展开/给我看/显示」+ 已知插件名或面板名

窄规则**宁缺毋滥**：只认强信号（动词与宾语都来自有限集合），漏报即退化为可点行、用户点一下，语义仍然通顺；误报的代价是抢屏，因此宁可漏。

> 不做「让 LLM 自行声明 explicit」：守门人不能是被守的人，模型有系统性动机把自己的调用标成用户要求的，而误判方向不对称。

## 5. 协议改动

只有一处。`[[tool]]` 上新增 `presentation`（`inline|peek|stage|focus`）与 `attention`（`quiet|suggest|focus`）。

**声明位置的关键区分：属于 `[[tool]]` 而非 `[[panel]]`。** `[[panel]]` 上已有的 `surfaces`/`min_width` 描述**面板的能力范围**（静态属性）；`presentation` 是**单次调用的建议**——同一个 `notes:list` 面板，被 `keep` 触发时该 inline（只是「记下了」的回执），被 `list` 触发时该 stage（用户要浏览）。声明在 panel 上无法区分。

同理，`explicit` 是**单次调用**的属性，静态声明覆盖不了，这也是它不进 manifest 的原因。

**实现：** tool 的 manifest 字典在 `plugins.py:555-562` 整体传进 `DeclarativeTool(pid, spec, registry)`，故在 `DeclarativeTool.__init__`（`:130`）内读取即可，无需改 loader。合法值集合复用 `_SURFACE_LEVELS`（`:29`），非法值静默过滤。

注入点只有一个：`DeclarativeTool.run()`（`:172-184`）已经有一处「成功才回填 `panel`」的后处理，表面建议在同一处回填即可——**不必逐个改 7 处 `ActionResult(success=True)` 返回点，也不需要 helper**。「失败不带表面建议」这条因此与既有的「失败不放 panel 引用」共用同一个 `if result.success` 判断，天然一致。

**声明：** `notes.keep` 加 `presentation = "inline"`。`list`/`delete` 不加，保持默认推断。

## 6. 明确不做

- ❌ **小窗不做卡。** 见 §2.1——它不承载撤销，多提供的信息接近于零，却在 360px 里顶满一整块。
- ❌ **小窗不做 ActivityShelf。** 大窗的底部横条存在是因为大窗主体是工作面、对话只占一栏；小窗主体就是对话流，行天然按时间排列，再挂横条是重复。
- ❌ **不动大窗。** `InlineReceipt` / `PeekSurface` / `ActivityShelf` 一律不改，包括不给 `InlineReceipt` 的「忽略」改名——那个改名的理由（小窗降密度语义）随卡一起消失了。
- ❌ **不加 `count` 协议字段**（`data.rows` 已够，且缺失可自然降级）。
- ❌ **不加 `explicit` 协议字段**（前端信息已足）。
- ❌ **不做 `autoMax` 入参化**（裁决器现有封顶已使硬规则自动成立）。
- ❌ **不抽共享 `useBrainSurface` 层**（五处 `case "panel"` 职责各异）。
- ❌ **旧行不存快照、不重放动作**（见 §2.4）。

## 7. 测试策略

**sidecar（pytest）：** 声明式 tool 携带 `presentation`/`attention` 进 `ActionResult`；非法值静默过滤；不声明时回落默认（`None` / `"suggest"`）；失败分支不带表面建议。

**前端（vitest）：** 两个纯函数必须可测。窄规则匹配——命中「打开闪念盘」置 explicit、未命中不置、动词或宾语任一不在集合内不置。形态映射——`stage`/`focus` 且 `show` 才开窗，其余一律出行，`show=false` 时即便带 `stage` 也不开窗（双保险，硬规则不依赖单一判断）。

按 `origin` 补表面属性的逻辑（找得到就补、找不到就建、新事件让旧行失活）同为纯状态函数，一并单测。

`decideSurface` 本身**不改动**，其 11 条既有单测即为回归防线。

**真机验收**（自动化不可覆盖）：

1. 小窗说「记一下这句话」→ 过程行原地变成 `闪念列表 · N 条 ›`，**不新增一行**、不开浮窗、宠物窗不收回球形态
2. 小窗任何模型自动调用 → 不开浮窗
3. 小窗说「打开闪念盘」→ 窄规则命中 → 直接开浮窗
4. 小窗点插件视图里的插件 → 开浮窗（**回归项**）
5. 连记三条 → 只有最新一行可点，其余转为不可点，流不刷屏
6. 无面板的动作（如记忆写入）→ 过程行仍显示 `✓`，不受影响
7. 大窗说「记一下这句话」→ Inline 回执而非 Peek（补齐 Phase 1 验收条 ①）

### 协议（§5）

`[[tool]]` 的 `presentation`/`attention` 在 `DeclarativeTool.__init__` 读取，非法值静默过滤。**注入点只有一个**：`run()` 里既有的「成功才回填 `panel`」后处理块——写计划时曾以为要改 7 处 `ActionResult(success=True)` 返回点并加 helper，实际那处后处理已经是唯一收口，「失败不带表面建议」因此与「失败不放 panel 引用」共用同一个 `if result.success`，天然一致。`notes.keep` 声明 `presentation = "inline"`。

### 窄规则的判据换过一次（§4）

初版按计划写成「句中含强动词 + 句中含插件名」两个全串 `includes`。评审两次驳回：`不要打开日历`、`别给我看日历`、`能打开日历吗` 全部误命中并抢屏。第一轮补否定/疑问黑名单被驳回——只覆盖了点名的三个样例，同类照漏。

**最终改为锚定判据：整句以强动词开头，且不以疑问语气词（吗/呢/？/?）结尾。** 否定、疑问、陈述都会把别的词放在动词前面，因而天然不命中，一条规则替掉整张黑名单。

代价记录在案且接受：`帮我打开日历` 因礼貌前缀破坏锚定而漏报，`打开闪念列表` 匹配不到名为「闪念盘」的插件。两者都退化成可点行加一次点击——这正是「宁缺毋滥」要买的东西。

### 表面属性的生命周期是本阶段最大的坑（§2）

按 `origin` 把表面属性补到发起它的过程行上，需要一张独立于 `procIdx` 的锚点表：`procIdx` 在 `action_result` 就删了，而 sidecar 的 `action_result` 先于 `panel` 发出（`loop.py:331` → `:337`），复用它则锚点永远查不到、每个面板事件都会另起一行。

围绕这张表暴露了两个计划没预见的缺陷：

**其一，`reloadMessages` 整体重建 `bubbles` 时只清了 `procIdx`。** 陈旧下标若仍落在新数组内，随后的面板事件会把 `surface` 写到一条**不相干的历史消息行**上；而模板按 `b.surface` 分支渲染，那条消息的正文会直接从流里消失。修法是在 `procIdx.clear()` 旁并列清空——这是第七处改动，超出计划限定的六处，但把新状态的失效点放在它孪生状态旁边正是「按 run 有界」的应有之义。评审复核确认重建是唯一失效路径：全文件对 `bubbles` 只有 push、按下标改字段、整体重建三类写法，没有 `splice`/`shift` 这类会造成下标平移的操作。

**其二，`server.py` 有两条发 panel 事件却不带 `origin` 的路径**——`_emit_refresh_panel`（`:278`）与 `handle_panel_action`（`:339`，面板窗里**每次点按**都走）。`server.py` 全文没有 `origin`，只有 `loop.py` 挂。于是面板协作期间每次点击都命中「找不到锚点就追加」分支，往流里压一条灰行，收窗回来是同一个面板标题重复若干条。旧实现用 `if (!panelOpen.value)` 挡住过这个场景，那条保护随旧气泡一起删了，**注释却留在 `App.vue:128`**。

改为三段规则：①有 `origin` 且锚点命中 → 写该行；②否则倒查同 `panel` 的最近一条表面行 → 原地更新；③否则追加。规则 ② 同时收口了插件视图启动（无 `origin`）后连续窗内点击的堆叠。一个易写反的细节：`deactivateAll` 原地改写既有对象，而三条规则一律赋**新对象**，所以「先失活后置活」对复用分支同样成立。

### 与设计的偏差

**一处，在 §2.3 与 §4。** 两节都写「行的点击 = 置 explicit 标志后 `openPanel()`」，并把「可点行的点击」列为 explicit 的第二个来源。实装的 `openPanelWindow()` **不置标志**。

这个偏差是对的，设计写错了：标志的作用是让**后续到达的** panel 事件被判为 explicit，而行点击只开窗、不触发任何新的工具调用，没有后续事件需要它。开窗后在窗内点击走 `handle_panel_action`，事件既无 `origin` 也无 hints，小窗算出 `peek` 落成行——而窗已经开着，无害。

因此 explicit 实际只有**两个**来源（插件视图点击、窄规则），不是三个。

### 终审后的三处修复

全分支评审判 **Merge with fixes**，两条 Important 都直接打在验收条 ③ 上，且都是计划阶段没看见的：

**其一，窄规则在默认路径上恒不命中。** `plugins.value` 的唯一填充者是插件视图的 `expandTo`，用户没进过插件视图它就是空数组，而 `matchExplicitOpen` 第一行就 `if (!plugins.length) return null`。也就是说**每次冷启动后「打开闪念盘」都不开窗，直到用户先去插件视图逛一圈**——整个窄规则在主路径上是哑的，且失败表现为「时灵时不灵」，排查会跑偏。改为挂载时加载（`list_plugins` 是本地 Rust 命令，`HomeChat`/`AgentBrain` 早有同样先例），并把匹配用的列表与插件视图的 `.slice(0, 8)` 展示列表分开——截断不该限制能匹配到什么。

**其二，8 秒时间窗是从错误的路径抄来的。** 该值抄自 `HomePlugins.vue:184-185`，那里计时起点紧挨着一次直调 `panelAction`（百毫秒级）。而 `submit` 这条路的起点是用户回车，终点是 panel 事件，中间隔着「LLM 决定调插件」和「LLM 再决定调 list」两轮往返加工具执行，5–15 秒很正常。**8 秒是掷硬币，且输了以后静默降级**——窗就是不开，不报错。改为不用墙钟：`markExplicit` 只记插件，标志在 run 终止（`final_reply` / `error` / `interrupted`）与每次 `submit` 起始清除。这同时消掉了「无关面板事件偷走时间窗」那条遗留 Minor，无需单独加守卫。

**这三处修完之后，复评又抓出一个更糟的：其一的修法本身把泄漏从 8 秒放大成了无限期。** 把自动过期的标志换成必须显式清除的标志之后，`launchPlugin` 的**成功**路径没有任何清除点——直调走 `handle_panel_action`，它发完 panel 事件只写 `run_done`，不产 `final_reply`/`error`/`interrupted`，而小窗压根没订阅 `run_done`（`brain.ts:217` 的 `onRunDone` 当时全仓零调用者）。8 秒窗虽然套不住文本路径，却一直在兜这个底。

后果之一正是验收条 ② 要禁止的：语音输入不经过 `submit`、拿不到起始清除，于是插件视图启动过一次之后，该插件在任何一次语音对话里的自动面板事件都会弹窗。之二是面板窗内每次点击都被判 explicit，重新 show+focus 并把展开的小窗强制收回球形态。

订阅 `onRunDone` 清除即闭合——它是「直调成功」「直调四种早退」「agent run 三种收尾」唯一共有的信号。同时移除 `error` 分支的清除：`error` 并非 run 终态（`loop.py:319` 用户拒绝确认、`:324` 策略禁止，都是 yield 之后 `continue`），在那里清会让同一轮里稍后到达的面板事件被判非 explicit，用户要的窗反而不开。

**其三，行上渲染出了三段点号。** sidecar 给的 title 本身已是全限定的（`plugins.py:387` 拼 `插件名 · 面板 label`），再接计数就成了 `闪念盘 · 闪念列表 · 3 条 ›`，在 360px 里会折行，也与 spec 和验收清单写的 `闪念列表 · N 条` 不符。在 `App.vue` 构造表面属性时剥掉插件前缀（`SurfaceLine` 保持无脑渲染）。

### 待真机验收

自动化覆盖不到，需在 `npm run tauri build -- --debug` 出包后逐条确认（对应计划 Task 6 Step 2 的七条）：

1. 小窗说「记一下这句话」→ 过程行**原地**变成 `闪念列表 · N 条 ›`，不新增一行、不开浮窗、宠物窗不收回球形态
2. 小窗任何模型自动调用 → 不开浮窗
3. 小窗说「打开闪念盘」→ 窄规则命中 → 直接开浮窗，且流里那一行仍可点
4. 小窗点插件视图里的插件 → 开浮窗（**回归项**：接裁决器后若不置 explicit 标志会静默失效）
5. 连记三条 → 只有最新一行可点，其余转灰，流不刷屏
6. 无面板的动作（如记忆写入）→ 过程行仍显示 `✓`，不受影响
7. 大窗说「记一下这句话」→ **Inline 回执**而非 Peek（补齐 Phase 1 验收条 ①）

另有一条评审提出、自动化与静态分析都判不了的：行点击重开浮窗时窗内容是否正确，取决于 Rust `open_panel_window` 是复用隐藏窗还是重建，而 `src-tauri` 与 `PanelApp.vue` 都在本阶段禁改范围内。

### 遗留 Minor（终审已 triage）

**同根的两条，建议一起做：** 倒查找无距离下限（有 `origin` 但锚点已被 `submit` 清空时，可能改写视野外的老行），以及 `surfaceAnchor` 仅在 `submit` 清空（自发 run 如提醒、晨间反刍若产生过程行但无面板事件，锚点会留到用户下次说话）。两者的根因都是锚点生命周期挂在 `submit` 上而非挂在 run 上——改成随 run 结束失效，两条同时消失，倒查兜底也就很少被走到。

**同处的两条，也建议一起做：** `reloadMessages` 从 DB 重建时 `surface` 不在持久化字段里，会丢掉活的表面行；而 Rust 侧 `event_recorder.rs:223-232` 仍在持久化本分支已删掉的「⇢ 正在和「X」协作」（`upsert_panel_link`）。于是实时渲染与重建渲染现在讲两套模型——live 是「一行带表面属性」，重启后是「一条 ✓ 过程行 + 一条协作气泡」。注意 `panelLink` 这行 DB 数据还在给大窗 `HomeChat.vue:822` 的关联按钮供数，不能直接删 `on_panel`。

**`run_done` 的粗糙是买来的，别顺手"优化"掉：** 它不带 surface、跨窗广播，所以一次无关 run 结束会提前清掉 explicit 标记，用户明确要求的窗静默不开。但这个粗糙同时兜住了两件事——`submit` 那轮只发 `error` 不发 `final_reply` 的 run 不会泄漏标记，以及 sidecar 崩溃后残留的标记能自愈。失效方向是「该开的没开」，退化成一条可点行，**永远不会反向违反「模型不得自动开窗」**。若将来要收紧，`brain.ts:171-177` 的 `panelAction` 支持外部传 id，可在 `launchPlugin` 内自铸 rid 并在回调里比对——但必须保留 `submit` 侧的无条件清除，否则会把上面那个洞重新打开。

**其余：** `panelOpen` 退化为只写状态（原为协作气泡去重服务，该 push 已删；删除时应在注释里留一句它曾承担跨窗去重）；规则 ② 按 `panel` id 去重而非按插件，钻取到子面板仍会新增一行；三条归属规则约 35 行内联在 `case "panel"`，spec §7 原打算把它也做成可单测的纯函数，抽成 `attachSurface(rows, attr, at)` 约十行即可与另外三个单元齐平；sidecar 非法值用例只覆盖了 `presentation`，未覆盖 `attention`；sidecar 没有一条测试同时覆盖 `presentation` + `panel` + `refresh`——而 Gap A 真实走的恰是「refresh 把 payload 整个换掉」这个接缝（终审读过三个返回点确认当前正确，但这条不变式没有测试守着）。
