# 移动端 M1（基建 + 会话体验）实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 手机端会话体验补齐：断线补帧、多会话列表+历史回显、Markdown 渲染+代码复制；基建上 HTTPS（mkcert）+ PWA。执行分三席：T1（server）、T2+T3（mobile 补帧+渲染）、T4+T5（会话+基建）。

**Architecture:** server 加 `/v1/conversations`/`/v1/history`（复用 ConversationHistory 桶）与 SSE `last_event_id` query 兜底；mobile events.ts 透传 seq 并在手动重连时续传，chat.ts 按 seq 去重；消息渲染 marked+DOMPurify；vite-plugin-mkcert 出 HTTPS，manifest 出 PWA。

**Spec:** `docs/superpowers/specs/2026-08-14-mobile-companion-design.md` §15 M1

## Global Constraints

- `sidecar/src/yibao_brain/server.py` 工作区有另一会话未提交 WIP：触碰该文件的提交必须 hunk 过滤（挑含本任务关键词的 hunk；核对暂存区后提交）
- 不引 pinia/axios；marked+dompurify+vite-plugin-mkcert 是 M1 新增仅有的三依赖
- mobile 测试 vitest fake 注入；server 测试 pytest 函数级；先红后绿；中文注释
- ConversationHistory 每桶仅留最近 10 轮——历史回显以「最近上下文」定位，不做完整存档承诺（UI 文案不撒谎即可）

### Task 1:（server）conversations/history 端点 + SSE last_event_id query 兜底

**Files:**
- Modify: `sidecar/src/yibao_brain/http_api.py`（两路由 + events 的 last_event_id query）
- Modify: `sidecar/src/yibao_brain/server.py`（deps 接线：`_conversations()`/`_history(cid)` 闭包——从 agent 的 history 对象取，先 grep `history` 在 build_loop/serve_async 的挂点）
- Test: `sidecar/tests/test_http_api.py`（fake deps 路由级）+ `sidecar/tests/test_server.py`（serve_async 级：真 history 桶）

**Interfaces:**
- Produces:
  - `GET /v1/conversations` → `{ok, items:[{id, preview, turns}]}`（preview=末条 assistant 文本前 50 字；turns=该桶消息数）
  - `GET /v1/history?conversation_id=x` → `{ok, items:[{role, text}]}`（无 id=默认桶）
  - SSE：`/v1/events?last_event_id=N` 与 header 等效（手动重连的 EventSource 新建时带不上 header，query 是唯一通道）
  - `MobileDeps.conversations: () -> dict`、`MobileDeps.history: (cid: str) -> dict`（deps 未接线 503，与既有路由一致）

- [ ] **Step 1: 测试先红**（http_api 路由级 fake + events query 兜底）——test_http_api.py 追加：conversations 200 形状断言；history 形状断言；`tap.publish` 两帧后 `GET /v1/events?token=..&last_event_id=1` 首帧行应为 `id: 2`。
- [ ] **Step 2: 实现**——http_api.py 两处理器+路由（未接线 503 模式照抄 v1_state）；`v1_events` 里 `last_seq = int(request.headers.get("Last-Event-ID") or request.query.get("last_event_id") or 0)`（ValueError→0）。server.py：grep `history` 挂点；`_conversations`/`_history` 读 `agent.history`（`messages(cid)` 现成；桶列表需读 history 内部 `_load()` 的键——若 `_load` 私有不便，给 history.py 加公开方法 `conversations() -> list[dict]`（id/preview/turns），history.py 无跨会话 WIP 可正常提交）。serve_async deps 接线两行。
- [ ] **Step 3: test_server.py 补 serve_async 级一条**：注入 use_real=False + 先经 reader 投一条 run 跑完（FakeProvider），再 GET /v1/conversations 含该会话。若 reader 模式成本高，可退而测 `build_loop` 产物的 history 桶 + `_conversations` 闭包直调（测得到形状即达标）。
- [ ] **Step 4: 全量 `uv run --extra dev pytest -x -q` 绿 → hunk 过滤提交**（server.py 只挑 conversations/history 关键词 hunk）`feat(server): /v1/conversations+/v1/history + SSE last_event_id query 兜底`。

### Task 2:（mobile）seq 补帧——lastEventId 透传 + 手动重连续传 + 帧去重

**Files:**
- Modify: `mobile/src/api/events.ts`（handler 签名带 seq；`lastSeq` 跟踪；`buildEventsUrl` 支持 `lastEventId` 参数）
- Modify: `mobile/src/state/chat.ts`（按 seq 单调去重；5s 兜底重连传 lastEventId）
- Test: `mobile/src/api/events.test.ts`、`mobile/src/state/chat.test.ts`

**Interfaces:**
- Produces:
  - `EventSourceLike` 的 addEventListener 回调收到 `(e: { data: string; lastEventId: string })`
  - `on(kind, fn)` 的 fn 签名 `(data: any, seq: number)`；`useEventStream` 返回值加 `lastSeq: Ref<number>`
  - `buildEventsUrl(c, lastEventId = 0)` → `...&last_event_id=N`（N>0 时）
  - chat.ts：`seenSeq` 单调（seq<=seenSeq 的帧整帧丢弃）；Chat.vue 的 5s 兜底 start 改为 `stream.start()` 前更新 url 闭包（useChat 的 url 工厂读 `stream.lastSeq.value` 生成带 last_event_id 的 URL）

- [ ] **Step 1: 测试先红**：events.test 补「fake ES 发 lastEventId: "5" 的帧 → on 回调 seq===5、lastSeq.value===5；buildEventsUrl 带 lastEventId 拼 query」；chat.test 补「重放旧 seq 帧被丢弃（同文本不重复拼接）」。
- [ ] **Step 2: 实现三处** + `cd mobile && pnpm test && pnpm build` 绿 → 提交 `feat(mobile): SSE seq 补帧——lastEventId 透传/手动重连续传/帧去重`。
